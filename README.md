## OpenClaw 到底吃多少内存

同一个软件，配置要求能被说成 1G 能跑和 8G 起步两个极端，差的是服务器上让它干什么。把几家的口径排在一起就清楚了：

| 你在服务器上跑什么 | 需要的内存 | 对应哪一档 |
| --- | --- | --- |
| 只调云端大模型 API，一个人用，接一两个渠道 | 1–2GB，加一块 swap 更稳 | KVM 入门版 2 核 2G，¥10/月 |
| 接微信、飞书、QQ，几个人共用，或要跑浏览网页类任务 | 4GB | KVM 标准版 2 核 4G，¥19/月 |
| 自己从源码构建 Docker 镜像 | 6GB 以上 | KVM 专业版 4 核 8G，¥58/月 |
| 同机再跑 n8n、数据库、其他常驻服务 | 8GB 起 | 专业版或旗舰版 |

依据分散在各家文档里。OpenClaw 官方给 DigitalOcean 写的部署指南用的是一台 1 vCPU、1GB 内存、25GB 硬盘的 Basic 套餐，月付 $6，前提是走云端 API 模型，1GB 要加 swap；官方同时标注 2 核 2G 和 2 核 4G 用预构建 Docker 镜像，2 核 8G 那一档写的是「建议用于源码构建镜像」。阿里云 ECS 文档建议 4vCPU 4GiB 及以上；AWS 官方文档推荐 4GB；腾讯云国际把 2 核 4G 标成主推、2 核 2G 标成个人轻量用。一个单人闲鱼运营场景的实测方案里，2 核 2G 就够跑自动回复和自动发货，一年服务器成本 400–600 元。

预算卡在 ¥10 一个月，就买 2 核 2G，加 swap，安装时用官方预构建镜像，别在机器上编译。内存耗尽时 Linux 会按 OOM 机制杀进程，OpenClaw 的处理是让临时子进程先死、尽量保住网关，被杀的进程退出码常见 137，看到这个数字基本就是内存不够。

小机器和 ARM 机器执行命令偏慢，可以在 systemd 覆盖配置里开 `NODE_COMPILE_CACHE`、设 `OPENCLAW_NO_RESPAWN=1`、把 `TimeoutStartSec` 调到 90 秒，改完重启生效。是不是 ARM，登进去敲 `uname -m`，显示 aarch64 就是。

## 买之前没人告诉你的四件事

**一、关机不省钱。** Vultr、DigitalOcean、Hetzner、Lightsail 都按小时计费，关机照扣，删掉才停。雨云走的是月付/年付套餐口径，不存在「关机能省几毛」这回事，不用了就等下个周期不续。所以试错别用包月：先用 1 元试用或者积分兑换的低配实例验证装不装得上，再决定买哪档。

**二、长约价要按年看。** Hostinger 托管版的 $4.99/月、VPS 的 $6.49/月，Contabo 的 $5.28/月，都是签满 24 个月、一次付清的月均价；Hostinger 托管版续费从 $4.99 跳到 $11.99，翻了一倍多。雨云年付 7 折的前提是一次付满 12 个月，跟你第二年续不续、按什么价续是两件事。

**三、模型是第二张账单。** OpenClaw 软件本身开源不收钱，钱花在服务器和模型调用上。Lightsail 那条路尤其明显：服务器是一张账单，每条消息走 Bedrock 还按 token 另计费，用第三方模型可能还有 Marketplace 的软件费单列。选便宜的服务器省下来的钱，可能不够模型多聊几轮，选模型时把单价一起算。

**四、来历不明的预装镜像要看启动脚本。** OpenClaw 官方的 DigitalOcean 指南专门提醒过，别用来路不明、没看过启动脚本和防火墙默认值的第三方 Marketplace 一键镜像；公网机器装之前先把 SSH 管好。自己装虽然慢，至少每一行命令都是你敲的。用宝塔面板这类预装环境的话，创建完实例第一件事是改默认 root 密码和面板密码。

## 装好先做的三件事

OpenClaw 的 Gateway 默认只听 `127.0.0.1:18789`，只有本机能访问。要在自己电脑上打开控制台，用 SSH 隧道最省事：


ssh -L 18789:127.0.0.1:18789 root@<服务器公网IP>


然后在本地浏览器开 `http://localhost:18789`。

想直接把网关绑到局域网上，得先设共享密钥，token 或 password 都行，再 `openclaw config set gateway.bind lan` 加 `openclaw gateway restart`，并在安全组放行入方向 TCP 18789，授权对象填自己办公室或家里的出口 IP 段，别填 `0.0.0.0/0`。没设密钥又把网关绑出去的机器，等于把 Agent 的控制台摆在公网上让人点。

SSH 这一头也别省：用密钥登录、关掉密码登录、能限制来源就限制。用 Docker 部署的话，还要看 Docker 的 `DOCKER-USER` 防火墙链，默认那几条规则会绕开你手写的 iptables。
